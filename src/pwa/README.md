# donkai-pwa

Mobile-first PWA dashboard for Donkai — "a dev in my phone".

## Commands

```sh
pnpm --dir src/pwa install         # install deps
pnpm --dir src/pwa dev             # vite dev server (proxies /api + /healthz -> localhost:8346)
pnpm --dir src/pwa build           # production build -> src/pwa/dist
pnpm --dir src/pwa exec tsc --noEmit  # typecheck
pnpm --dir src/pwa run icons       # regenerate PNG icons (zero-dep node script)
```

The Hono server serves `dist/` at `/` with SPA fallback, so any client route
(`/queue`, `/ticket/ENG-12`, …) resolves to `index.html`.

## Auth

Token is entered at runtime and stored in localStorage under `donkai_token`.
Every API call sends `Authorization: Bearer <token>`; a 401 drops back to the
token screen. No secrets are baked into the app shell.

## Push notifications

The service worker is generated by vite-plugin-pwa (generateSW) and pulls in
`public/push-sw.js` via `importScripts` for `push` / `notificationclick`
handling. Expected payload: `{title, body, kind, ticketKey, url}`.

## Notes / limitations

- Icons: `icon-192.png`, `icon-512.png` and `apple-touch-icon.png` are flat
  PNGs generated by `scripts/gen-icons.mjs` (hand-rolled PNG encoder, no
  dependencies). Regenerate with `pnpm run icons` if you change the SVG.
- The service worker (and therefore the push toggle) only exists in production
  builds; in `vite dev` the notifications toggle will report push as
  unavailable. Build and serve `dist/` through the Hono server to test push.
- Live updates poll (`/status` 4s, logs 2.5s) rather than using `/events` SSE,
  keeping the client simple and resilient to flaky mobile connections.
